# Deploy on Render (with Supabase)

1. Use the existing `l70478519-cloud/Kenya-campaign-manager` repository, branch `main`, root directory blank.
2. In Render choose **New → Blueprint**, connect the repository; Render reads `render.yaml`.
3. Set the environment variables below. For a new empty database, apply the base schema before starting the web app: from a checkout with dependencies installed, set `DATABASE_URL` and run `pnpm --filter @workspace/db run push`. Review the proposed SQL; do not use `push-force` or the reset script. Startup adds operational and campaign-isolation tables. Deploy after schema preparation.
4. Open `https://<your-service>.onrender.com/` (website) and `/login` (the app).

| Variable | Required | Value |
|---|---|---|
| `DATABASE_URL` | yes | Supabase **Session Pooler** connection string |
| `SESSION_SECRET` | auto | generated by Render |
| `MFA_ENCRYPTION_KEY` | auto | generated by the blueprint; preserve this key; never change after people enrol in 2FA |
| `BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_USERNAME`, `BOOTSTRAP_ADMIN_PASSWORD` | first run | creates the first super-admin |
| `PRIMARY_SEAT` | optional | `President`, `Governor`, `Senator`, `Woman Rep`, `MP` or `MCA` for campaign #1 |
| `PRIMARY_COUNTY`, `PRIMARY_CONSTITUENCY`, `PRIMARY_WARD` | optional | the area for that seat (e.g. `Makueni`, `Kaiti`) |
| `PRIMARY_CANDIDATE`, `PRIMARY_CAMPAIGN_NAME`, `PRIMARY_ORGANISATION_NAME` | optional | names shown in the app |
| `MFA_REQUIRED_ROLES` | optional | empty by default (password-only sign-in until 2FA is voluntarily enabled); set a comma-separated role list to enforce enrolment |
| `MAKUENI_AI_MODE` | optional | `free` to run AI features from templates without an AI key |
| `AI_INTEGRATIONS_OPENAI_API_KEY`, `AI_INTEGRATIONS_OPENAI_BASE_URL` | optional | AI provider |
| `SITE_AT_ROOT` | set | `true`: website at `/`, app at `/login` |
| `CORS_ORIGINS` | optional | only if the website is hosted on a different domain |

After the first deploy, check the log for `Campaign isolation active`. If you skipped
`PRIMARY_SEAT`, sign in and open **Organisations & campaigns → Set seat & area**.

## Custom domain
In Render → your service → Settings → Custom Domains, add your domain and create the DNS
records Render shows (at your registrar or cPanel DNS). Keep the app and `/api` on the same
Render service so sign-in cookies work without extra configuration.

## Verification after connection

`/api/healthz` only checks the process, not database readiness. Confirm schema preparation and startup logs, sign in with the configured bootstrap account, create two campaigns with different areas, and check record isolation before loading real data. The original Python prototype is retained in `starter/` and is not used by this deployment. Do not execute `supabase/controlled-operational-reset.sql` during normal setup.
